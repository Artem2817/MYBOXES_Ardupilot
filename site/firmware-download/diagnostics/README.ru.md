# MayboxDiag 0.1.0

Отдельное стендовое приложение для STM32H743 и русская программа для Windows/Linux. Разработано с помощью AI. Не является полётной прошивкой.

## Готовые файлы

- `dist/firmware/MayboxDiag-0.1.0-MyboxH743_mini.hex` — старая Mini, ICM-42688-P + MS5611.
- `dist/firmware/MayboxDiag-0.1.0-MyboxH743_mini_v2.hex` — V2 без вибро, ICM-45686 + SPA06-003.
- `dist/firmware/MayboxDiag-0.1.0-MyboxH743_mini_v2_vib.hex` — Vib, дополнительно ICM-42670-P + SPA06-003/0x77.
- `dist/windows/MayboxDiag/MayboxDiag.exe` — программа Windows x64, Python отдельно не требуется. Сохраняйте рядом всю папку `_internal`.
- `examples/demo-report/` — пример JSON/HTML/CSV, полученный **в демонстрации**, без физической платы.

Все три аппаратных профиля используют STM32H743xx, HSE 8 МГц, 2 МиБ Flash. Один HEX на все разводки не применяется. Профиль выбирается при сборке; аппаратного определения ревизии нет. Ориентация IMU берётся из профиля (`ROTATION_NONE`).

## Что проверено

В текущем сеансе физических плат нет. Подтверждаются компиляция, границы HEX, программные проверки протокола/отчётов/ориентации, обмен через виртуальный последовательный порт и запуск интерфейса/Windows EXE в демонстрации. Реальное подключение USB, показания и направление поворотов платы предстоит проверить на стенде. Список критериев — `docs/ACCEPTANCE.ru.md`.

Реализованы прямое чтение и настройка всех заявленных IMU, оба типа барометра, АЦП, регистры/тестовый экран OSD, отдельный файл SD read/write, чтение части внутренней Flash, UART loopback, CAN с внешним ответчиком, декодированные кадры RCIN, LED/safety/зуммер и ограниченный PWM-тест. Полный цикл после старта работает без ПК. Ошибка одного датчика не вызывает общий `panic`.

Ограничения: встроенное возбуждение self-test и сравнение OTP IMU, драйверы произвольного внешнего компаса, активный нагрев, DShot-генератор диагностики и запись внутренней Flash не реализованы. Это отдельные предупреждения/непроведённые проверки, а не успешные результаты. Нет выделенной безопасной области для записи Flash; настройки и калибровки не изменяются. Подробная таблица — `docs/COVERAGE.ru.md`.

## Прошивка на стенде

1. Снимите пропеллеры, отключите опасные нагрузки. Сохраните параметры и подходящую штатную прошивку конкретной ревизии.
2. Сверьте название профиля с платой. Не пробуйте HEX другой разводки для определения ревизии.
3. HEX содержит **только приложение по адресу 0x08020000**. Последние 256 КиБ Flash исключены из области приложения. Загрузчик, option bytes, защиты и постоянные калибровки приложение не программирует.
4. Запишите HEX через STM32CubeProgrammer в аппаратном DFU или через SWD. Не выбирайте полное стирание чипа и не меняйте option bytes. При записи стираются только необходимые сектора приложения; параметры в последних двух секторах сохраняются.
5. Для обычной загрузки с 0x08020000 нужен совместимый установленный загрузчик ArduPilot соответствующей платы. Если сейчас установлен INAV без загрузчика ArduPilot, сначала сохраните его образ и используйте SWD для запуска приложения с вектором 0x08020000 либо отдельно восстановите подходящий загрузчик штатным способом. Сам диагностический HEX загрузчик не добавляет. Запись приложения по смещению на пустой MCU сама по себе не обеспечивает загрузку после сброса.
6. Перезапустите плату. Она начинает стартовый цикл самостоятельно; USB CDC доступен для программы ПК. Подключите USB-кабель с передачей данных. Для известной схемы USB-C без Rd может потребоваться USB-A→C.

Программа не выполняет прошивку платы автоматически. Возврат к штатной прошивке описан в `docs/RETURN.ru.md`.

## Программа ПК

Откройте `MayboxDiag.exe`, выберите COM-порт и нажмите «Подключить». Ручной ввод порта поддерживается. При необходимости включите автоподключение. Программа запрашивает информацию, перечень тестов и результаты стартового цикла, включает поток 20 Гц. Диапазон потока — 0–100 Гц; 0 выключает его.

«Полная диагностика» останавливает текущий тест и запускает общий безопасный цикл. Активные PWM/LED/зуммер, SD-запись и тесты с внешними устройствами выбираются отдельно. Внизу таблицы видна инструкция по выбранному тесту. «Подтвердить» разрешено для визуального/звукового наблюдения или внешнего PWM-измерения; оно не заменяет автоматическую проверку ID, UART или CAN.

Во вкладке «Положение платы» выберите IMU. «Установить ноль» меняет только представление на ПК. Крен/тангаж корректируются по направлению силы тяжести, курс относительный и может дрейфовать. Внешнего абсолютного источника курса в этом приложении нет. При длительном отсутствии свежих данных оценка не обновляется. Расчётная ориентация не доказывает исправность всех датчиков.

Во вкладке «Показания» показаны единицы, время с последнего измерения, частота принятых измерений и частота пакетов на ПК, ошибки, исходные отсчёты и коэффициенты АЦП. Частота DRDY-опроса — наблюдаемая частота получения; при перегрузке это не точное измерение внутреннего генератора ODR. В графиках можно выбирать канал, менять масштаб мышью, включать автомасштаб и приостанавливать просмотр без остановки записи.

Сеанс автоматически записывается в `MayboxReports/<UUID>/`: CSV телеметрии, JSONL событий, JSON/HTML отчёт. «Сохранить отчёт» экспортирует JSON, HTML и CSV в выбранную папку. Каждое подключение создаёт новый сеанс; прежние файлы сохраняются. В отчёте видны UID, профиль сборки, версия, автоматические результаты и подтверждения оператора. Неполные проверки не становятся успешными при отключении.

Демонстрация: кнопка «Демонстрация» или `MayboxDiag.exe --demo`. Данные синтетические, UID начинается с DEMO; маркировка сохраняется во всех отчётах.

## Из исходников ПК

Windows: Python 3.11/3.12 x64, затем `pc/start-windows.cmd`. Этот сценарий создаёт отдельное окружение и устанавливает фиксированные зависимости. Для упаковки EXE — `pc/build-windows.cmd`.

Linux:

```sh
python3 -m venv .venv
.venv/bin/pip install -r pc/requirements.txt
.venv/bin/python pc/run.py --demo
```

Используются официальные модули PySide6 Essentials (QtWidgets/QtGui/QtCore), pyserial, pyqtgraph и numpy. Пространственная схема рисуется QPainter, отдельная OpenGL-библиотека не нужна. На Linux нужны системные библиотеки Qt/X11/Wayland; для программной проверки `QT_QPA_PLATFORM=offscreen`.

## Сборка прошивки

Нужен **отдельный** checkout ArduPilot, ARM GCC 10.2.1 (2020-q4-major), Python 3.12 с зависимостями ArduPilot, make, git, rsync. Проверенная платформа: `046cafbceec1a30a202b2eefe64554e5ea54cf01` из MYBOXES_Ardupilot. Установите зависимости платформы по её документации. Все её подмодули должны быть доступны.

```sh
git clone --recurse-submodules https://github.com/Artem2817/MYBOXES_Ardupilot.git /tmp/maybox-diagnostic-platform
git -C /tmp/maybox-diagnostic-platform checkout 046cafbceec1a30a202b2eefe64554e5ea54cf01
git -C /tmp/maybox-diagnostic-platform submodule update --init --recursive
python3 tools/build_firmware.py --checkout /tmp/maybox-diagnostic-platform --jobs 4
python3 tools/verify_hex.py dist/firmware
```

Сценарий копирует только диагностическое приложение в `libraries/AP_HAL/examples/MayboxDiag`, создаёт отдельные HWDEF `MBD_Mini`, `MBD_V2`, `MBD_V2Vib`, отключает постоянное хранилище и функцию записи загрузчика. Исходные определения штатных плат не меняются. Включён `--consistent-build`, задан `SOURCE_DATE_EPOCH`; идентификатор диагностики вычисляется из исходников. В `dist/firmware` сохраняются HEX/BIN/ELF, манифест и SHA-256. Для полной побитовой воспроизводимости используйте тот же компилятор и версии подмодулей.

Данные профилей и полная распиновка — `profiles/*.json`, `docs/HARDWARE.ru.md`. Пороговые значения с обоснованием — `config/thresholds.json`; при сборке генерируется `firmware/thresholds.h`. Изменение профиля/порогов требует пересборки.

## Проверки разработки

```sh
PYTHONPATH=pc python3 -m pytest tests -q
python3 -m unittest discover -s tools/site_baseline/tests -p test_build_firmware_site.py
QT_QPA_PLATFORM=offscreen PYTHONPATH=pc python3 pc/run.py --smoke-demo --output examples/local-check
```

Проверяются повреждение/фрагментация кадра, тайм-аут неполного сообщения, переход номера через 2³², совпадение протокола C++/Python, строгие команды, виртуальный последовательный порт, отключение, отчёты, повороты и сохранность каталога сайта.
