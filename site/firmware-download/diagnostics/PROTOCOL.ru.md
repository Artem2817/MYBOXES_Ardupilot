# USB-протокол MBD/1

Транспорт — USB CDC, двусторонний бинарный поток. Скорость 115200 задаётся при открытии порта, для USB это метаданные линии. Прошивка не использует MAVLink/MSP и не принимает команды штатного конфигуратора.

## Кадр

Все числа little-endian; длина заголовка 16 байт.

| Смещение | Тип | Значение |
|---|---|---|
| 0 | 4 байта | ASCII `MBD1` |
| 4 | uint8 | версия 1 |
| 5 | uint8 | 1 запрос, 2 ответ, 3 событие, 4 телеметрия |
| 6 | uint16 | число байт JSON, максимум 4096 |
| 8 | uint32 | монотонный номер кадра отправителя, с переходом через 2³² |
| 12 | uint32 | время отправителя, мс; для устройства — uptime |
| 16 | bytes | UTF-8 JSON-объект |
| 16 + длина | uint32 | CRC-32/ISO-HDLC от заголовка и JSON, как `zlib.crc32` |

После повреждённого заголовка или CRC парсер сдвигается на один байт и ищет следующую сигнатуру. Неполный кадр сбрасывается после перерыва ввода более 250 мс. Резерв памяти ограничен; текст загрузки до первого кадра игнорируется. Версия и длина проверяются до разбора JSON. NaN/Infinity, дубли ключей и не-объект на ПК отвергаются. Команды устройства — строгий плоский объект с известными полями; вложенные значения и экранирование командных строк не используются.

Номер кадра позволяет обнаружить пропуск, но не является идентификатором запроса. `id` запроса — ненулевой uint32, возвращается в ответе. `seq` независим для каждого направления и увеличивается также при отброшенной из-за заполнения USB телеметрии. Через 2³² отсчёт продолжается с 0. Повторно применять активные команды по тайм-ауту автоматически нельзя.

## Запросы

Каждый запрос имеет `id` и `op`; остальные допустимые поля: `test`, `rate`, `duration_ms`, `channel`, `confirm`. Неизвестные поля — BAD_COMMAND.

| op | Поля | Результат |
|---|---|---|
| info | — | профиль, MCU, UID, версия, build ID, протокол, uptime, expected_devices, число датчиков/выходов |
| list | — | ACK, затем отдельные события `test`, завершающее `list_complete` |
| results | — | ACK, затем сохранённые события `result`, завершающее `results_complete` |
| run | test=all | безопасный полный цикл; активные/внешние шаги остаются `needs_action` |
| run | test=идентификатор | отдельный шаг; duration_ms 100–2000, по умолчанию 1000 |
| stop | — | прекращение активного вывода, отмена текущего шага/цикла |
| stream | rate=0…100 | частота групп телеметрии на ПК; 0 — выключить |
| ping | — | ACK, продление присутствия ПК |
| confirm | test, confirm=bool | только ожидающее визуальное/звуковое/PWM-наблюдение; фиксируется источник `OPERATOR_*` |

`run` для `pwm*.scope` требует `confirm=true`; GUI получает это значение только после явного подтверждения предупреждения о снятии пропеллеров. Канал PWM определяется ID теста. Произвольных адресов регистров и операций стирания/записи Flash в протоколе нет.

Примеры JSON до упаковки:

```json
{"id":1,"op":"info"}
{"id":2,"op":"stream","rate":20}
{"id":3,"op":"run","test":"imu0.stream"}
{"id":4,"op":"run","test":"pwm1.scope","duration_ms":1000,"confirm":true}
{"id":5,"op":"stop"}
```

Ответ ACK: `{"id":3,"ok":true,"code":"OK"}`. При занятом исполнителе — `BUSY`; неверный тест — `UNKNOWN_TEST`. После ACK результат приходит отдельным событием. Запрос `results` восстанавливает результат даже при потере исходного события.

`revision_source=build_profile`, `hardware_revision=null` означают выбранную при сборке ревизию. UID идентифицирует MCU, а не определяет разводку. `orientation_source=hardware_profile` — оси взяты из профиля.

## События и результаты

`test`: ID, device, method, automatic, applicable. Оборудование и выводы дополняются expected_devices и профилем JSON с SHA256 исходного HWDEF.

`result`: test, state, code, detail, expected, actual, duration_ms. Состояния: passed, failed, warning, not_tested, needs_action, not_applicable, running. Код и область проверки важнее одного зелёного статуса: например, osd.register проверяет только регистр, а видеотракт имеет отдельный osd.video.

`cycle_complete` завершает цикл. `link` передаёт uptime, parser_errors, dropped_tx, stream_hz, active_test. `error` сообщает BAD_COMMAND. Некорректный кадр без надёжного id не подтверждается.

## Телеметрия

IMU: `sensor=imu0/imu1`, sample_ms, sample_count, fresh, measurement_hz, configured_odr_hz, errors, saturated, accel_m_s2[3], gyro_deg_s[3], temperature_c, raw[7], rotation. Для ICM-42688/42670 raw = T, Ax, Ay, Az, Gx, Gy, Gz; для ICM-45686 = Ax, Ay, Az, Gx, Gy, Gz, T. Все каналы знаковые 16-битные; пересчёт зависит от full-scale профиля (16 g/2000 °/с или 32 g/4000 °/с).

Барометр: pressure_pa, temperature_c, relative_altitude_m, sample_ms, sample_count, fresh, measurement_hz, errors. Нулевая относительная высота задаётся первым корректным давлением после инициализации. Атмосферная формула не является независимой калибровкой высоты.

АЦП: raw, adc_voltage_v, scale, value, units, sample_ms, timestamp_source=hal_readout. АЦП HAL не предоставляет точного времени преобразования/частоты, поэтому measurement_hz=null; sample_ms — время чтения HAL. PC4 HWDEF SCALE(2) учтён один раз. Значение аналогового давления — напряжение после коэффициента 2, не Паскали неизвестного датчика.

`measurement_hz` IMU/барометра — средняя частота реально полученных DRDY/конверсионных выборок с инициализации; configured_odr_hz — настройка, частота на ПК считается отдельно по приёму. Передаётся последняя выборка, а не все 200 измерений в секунду. Потери USB не должны считаться поломкой датчика.

## Сроки и безопасность

Ответ ожидается до 2 с; отсутствие корректных кадров более 3 с завершает соединение ПК. Ping отправляется каждые 300 мс. На устройстве отсутствие команд более 2 с отключает поток. Активный PWM/LED/зуммер выключается независимым таймером после 750 мс без корректной команды или по установленному сроку, максимум 2000 мс. Все прочие каналы отключены.

Операции SPI имеют тайм-аут платформы около 20 мс + 32 мкс/байт, I²C — минимум 4 мс, захват семафора — 2 мс. Проверка SD выполняется в отдельном I/O-потоке; основной исполнитель прекращает ожидание через 6 с, не блокируя USB и датчики. Повторная операция SD невозможна до освобождения работника. Команда stop не может отменить уже начавшуюся внутреннюю файловую операцию; тестовый файл создаётся эксклюзивно и пользовательские файлы не затрагиваются.
