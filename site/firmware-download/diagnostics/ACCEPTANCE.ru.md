# Приёмка и физические испытания

## Программные доказательства

- `dist/firmware/*.log` — отдельная сборка каждого профиля.
- `dist/firmware/manifest.json`, SHA256SUMS.txt — версия, профиль, source build ID и контрольные суммы.
- `dist/firmware/hex-validation.json` — проверка каждой Intel HEX записи, отсутствия пересечений, адресов приложения, RAM stack/reset vector. Загрузчик и последние два сектора Flash не включены.
- `examples/test-results.txt` — проверки C++/Python протокола, malformed/partial/CRC, rollover, ориентации, отчётов, виртуального последовательного порта и отключения.
- `examples/site-baseline-tests.txt` — исходные проверки генератора существующего каталога.
- `examples/demo-report` и demo-window.png — запуск готового EXE; **демонстрация**, без платы.

Программные тесты не проверяют физические сигналы, аппаратный USB и измерительную точность. Текущая стадия — комплект для первого стендового испытания, полная аппаратная приёмка ещё не выполнена.

## Старая Mini: выполнить на физической плате

- Проверить загрузку приложения через сохранённый загрузчик и полное отсутствие PWM после включения без ПК.
- Проверить USB CDC, реальный UID, повторное подключение и выключение активного выхода при физическом отсоединении USB.
- Сверить ID ICM-42688-P, MS5611 PROM CRC и показания T/P/accel/gyro с условиями стенда.
- Выполнить покой/поворот по каждой оси, сопоставить модель платы с реальным движением. Курс должен быть подписан относительным.
- Проверить SD scratch-file без изменения существующих файлов, ёмкость и поведение без карты/при её сбое.
- Проверить OSD с камерой/монитором: регистры и реальное изображение как два отдельных результата.
- Проверить ADC напряжения/тока/давления/RSSI эталоном, при USB-only оставить неподключённые каналы непроверенными.
- Проверить каждый UART перемычкой, CAN1/2 внешним ответчиком, RCIN генератором/приёмником, каждый PWM осциллографом, LED/safety.
- Создать JSON/CSV/HTML отчёт с UID реального экземпляра и ручными подтверждениями; сохранить рядом стендовые измерения.
- Восстановить штатную прошивку и проверить её параметры/входы/выходы.

## V2 и V2 Vib

Повторить тот же цикл на каждой физической ревизии. Дополнительно проверить ICM-45686, SPI2 PC2_C/PC3_C, SPA06/0x76, I²C4 PB9/PD12, 13 выходов и комплементарные PB14/PB15, зуммер PB4, silent CAN и выключенный нагрев PA15.

Для Vib: реально установленный ICM-42670-P SPI1/PA4, SPA06/0x77, схему/контракт модуля J19, питание/FFC, взаимные оси и разницу двух IMU/барометров. В отображении используется ориентация из аппаратного профиля; физическая проверка осей входит в стендовую приёмку.

## Известные незавершённые функции

Полный встроенный self-test IMU, активный нагрев, DShot-тест диагностики, драйверы произвольного внешнего магнитометра, отдельная автоматическая проверка внешних I²C и RTS/CTS. Они перечислены в COVERAGE.ru.md и не засчитываются успешными. Их отсутствие нельзя скрывать зелёным итогом «всё оборудование исправно».
